# Design system

The map is the hero and the chrome recedes. MapCairn is calm, neutral and precise, with grouped controls, a floating search pill and a bottom sheet, in the way people already expect from a good maps app. Light and dark are equally polished. The target is WCAG 2.2 AA, built in from the first component.

Tokens live in `packages/theme/src/tokens.css.ts`. Components may only use tokens, so an off-scale value fails typecheck, and a lint test is the backstop for raw literals.

## Living style guide

`/design` renders every token and every primitive from the real code: colour roles with light and dark hex values and their contrast pairs, the type scale, spacing, radii, elevation, motion, z layers, the Lucide icons the app imports, each component in each state, and a font check that proves IBM Plex Sans is rendering. Open http://localhost:5173/design with `npm run dev`, or http://localhost:4173/design with `npm start` (the e2e build). The route exists only in development and in the `--mode e2e` build (`packages/web/src/designGuideRoutes.ts`); `npm run build` fails if the page's marker reaches the production bundle, and `e2e/design.spec.ts` covers it in the browser.

## Principles

1. One of everything: one family, one accent, one icon set, one stroke, one radius per role.
2. Every control has one owner of its position (`MapChrome`) and one layer (a named z-index).
3. Nothing is conveyed by colour alone.
4. Nothing needs a gesture, a hover or a mouse. Every gesture has a keyboard or single-tap equivalent.

## Tokens

- **Colour roles:** surface, surface-raised, text, text-muted, accent, accent-tint, hairline, danger, scrim, focus-ring, page-background, map-background, map-globe-space. The neutral ramp is OKLCH with a faint cool tint. The accent is one clear blue. Page-background follows the theme and sits behind full pages such as the privacy policy. Map-background is the default basemap's land colour in both themes, so the map region before the map draws matches the map that follows. Map-globe-space is the space around the sphere when the map is a globe, and only then: a cool mid grey in the light theme (`oklch(0.82 0.02 250)`), dark enough that pale land at the edge of the globe still shows and light enough to sit with the light chrome, and a dark blue in the dark theme (`oklch(0.31 0.025 255)`), dark against the dark chrome yet lighter and bluer than the near-black Dark basemap and the deep sea of the Satellite imagery, so their edges show too. A test keeps it at 1.2:1 or more against the land of every basemap the site offers, and the chrome text over it at 4.5:1.
- **Save data:** a switch in Settings, on by default when the browser reports a data saver or a `slow-2g` or `2g` connection (Chrome, Edge and Samsung Internet; iOS has no signal), and a stored choice always wins. While it is on, the picker shows names and a plain colour swatch (the basemap's own `swatch` colour, else the map background token) instead of thumbnails, Streets, Topographic and Satellite, whose tiles are images, carry the note "Uses more data", and a basemap leaves out the style layers it lists in `saveDataOmitLayers`. The SDK's Liberty, which the reference host does not offer, lists its shaded-relief raster layer (`natural_earth`), about a third of the first view's bytes; Bright, the default, Dark and the SDK's Fiord list none, because their styles draw no raster layer. The adapter removes them as each style loads, so no code names a basemap and data layers are drawn again afterwards. Switching it redraws the map once, only for a basemap that lists layers to leave out. Satellite still draws its imagery in Save data mode, because without it the map would be labels on nothing; it never asks for a tile deeper than level 14, where the imagery's real detail ends, and its tiles (14 to 23 KB each over Cape Town at levels 12 to 14, measured 2026-11-11) are a little smaller than the Streets tiles of the same place (22 to 35 KB).
- **Basemap:** Bright is the default in both themes. The basemap never follows the light or dark theme. The picker offers what the host supplies. The reference host offers six, in this order: Bright (the default), Positron, Streets, Topographic, Satellite and Dark, as manual choices like any other. They sit in a grid of three columns, two full rows of three. The SDK defines seven (`BASEMAPS`): Bright, Positron, Streets and Dark from the six, and Liberty, Colorful and Fiord, which a host may offer. Topographic and Satellite are not among them: the reference host defines them itself, Topographic so the SDK does not send every app built on it to a volunteer-run server, and Satellite because its imagery's licence is non-commercial. The reference host builds its own catalogue from a subset of the SDK's list and its own definitions, to ask fewer volunteer-run servers for tiles and to keep the picker short. A saved or linked id the host does not offer (`liberty`, `colorful` or `fiord`, the old "auto", or the retired `maptoolkit-dark`) opens on Bright, and a saved value is left alone. Topographic is OpenTopoMap, a free raster map with contour lines and shaded relief, defined by the host and under CC-BY-SA, with its credit in full: OpenStreetMap contributors, SRTM, OpenTopoMap and CC-BY-SA. It reaches zoom 17, as deeper levels return a blank tile. Satellite is a hybrid: EOX's Sentinel-2 cloudless imagery (CC BY-NC-SA 4.0, free for non-commercial use with credit) with the place names, roads and borders of OpenFreeMap Bright over it, because EOX's own labels overlay has no licence of its own. Its credit is shown in full and word for word: "EOxCloudless https://cloudless.eox.at by EOX IT Services GmbH (Contains modified Copernicus Sentinel data 2025)", the licence, a link to EOX::Maps (maps.eox.at), which EOX's tile service asks for, then the OpenFreeMap credits. The imagery's detail ends at zoom 14 and the map stops at 17, where the labels are still useful over the enlarged imagery. Only the style's lines and labels are drawn over the imagery, never its areas. Its appearance is dark, and its swatch is a dark green of the host's own, which is also the ground the map shows before the imagery draws. The WebMCP basemap tool does not offer it, because an agent should not accept a provider's licence on a person's behalf. Dark is OpenFreeMap's neutral dark style, and it asks for no more than the credit text the other OpenFreeMap styles carry. In the SDK, Fiord is OpenFreeMap's blue-toned dark style, and Colorful is VersaTiles' style, from a provider other than OpenFreeMap, which carries its credit text (OpenStreetMap contributors, VersaTiles, ESA WorldCover 2021 and the CC BY 4.0 licence it is under) and nothing else; its land colour is the default's, so it needs no swatch. A basemap with no preview image, or whose preview image fails to load, shows a plain swatch, as every basemap does in Save data mode. The SDK's definitions name no preview at all, so a host that serves none shows a swatch for each of them; the reference host adds previews for the six it offers (`BASEMAP_THUMBNAILS` in `packages/web/src/basemaps/basemapThumbnails.ts`). A definition may set `swatch`, a hex colour for that tile, so a dark basemap does not look like the pale default: Dark's and Fiord's are their styles' own land colours; Satellite's is a colour of the host's own, not sampled from the imagery. The picker applies it with a custom property set through CSSOM, never an inline `style` attribute. On it, the selected tile's check badge stays legible in both themes (the tick on the accent disc, and the disc or its raised-surface ring against the swatch, at least 3:1), and the name sits below the tile on the sheet. The SDK carries no provider whose licence it would have to accept; a host adds one as data (see `ARCHITECTURE.md`, host-supplied basemaps).
- **Data palette:** the one set of colours data layers draw with, separate from the interface roles. Seven Okabe-Ito categorical colours (without black) and a five-step ordered ramp, light to dark, in `tokenValues.dataPalette`. Definitions name a slot (`vermillion`, `ordinal-3`), never a value; categories must use categorical slots and steps ordinal ones. Every marker has a dark edge inside a white halo (`tokenValues.dataMarker`), the same on the map and in the legend, so the pale steps show on a light map and the dark ones on a dark surface; contrast tests cover both. Validation refuses a colour rule with no shape, size or words beside it.
- **Surfaces:** translucent with backdrop blur, with an opaque fallback and the `-webkit-` prefix. `prefers-contrast: more` and `prefers-reduced-transparency` make them opaque and remove blur. Contrast is computed over the worst-case backdrops (pure white and pure black map) and over the default basemap's land colour, because a dark theme no longer means a dark map.
- **Spacing:** 4, 8, 12, 16, 24, 32. Screen inset is 12.
- **Radii:** pill 24, sheet 20, control and card 14, inner 10. Fully circular elements use 50%.
- **Elevation:** two shadows, floating and sheet, each with light and dark values. No borders on floating elements. Hairlines only inside lists and between grouped controls.
- **Type:** IBM Plex Sans only, self-hosted through Fontsource (variable, Latin and Latin Extended), weights 400 and 600. Sizes 13, 15, 17 and 22, defined in rem with a line height and tracking each. Nothing below 13px. Numbers use `tabular-nums`. Inputs are 17px, never below 16px. The fallback stack is `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`, which also covers non-Latin place names.
- **Size:** controls are 48px minimum, targets never below 44px, switches and slider thumbs included (their hit area is larger than what they draw), with at least 8px between neighbours.
- **Icons:** `lucide-react` only, imported by name, 24px, one stroke-width token, through the `Icon` component.
- **Focus ring:** two tones (an inner surface ring and an outer ring, 2px each) so it shows on any basemap. Every interactive element and the focused map use it.
- **Motion:** 120, 200 and 320ms, one easing curve, one spring for the sheet. Only transform and opacity animate. `prefers-reduced-motion` turns motion off, including MapLibre's own animation.
- **Z layers, bottom to top:** map, mapOverlay, chrome, chromeRaised, sheet, toolbar, popover, toast. Components name a layer and never write a number. The tokens file and the map engine style file are the only places raw z-index values may appear.

## Layout and slots

`MapChrome` owns the position of everything floating over the map. It is `pointer-events: none`, and each slot's contents are `pointer-events: auto`.

| Slot | Contents |
| --- | --- |
| top-start | search pill |
| end-stack | compass (when the map is rotated), main control group (Map options, Measure, Directions when the host has a routing service, Draw shapes, Locate me, Settings), zoom control group (when shown) |
| bottom-start | scale readout, cursor coordinates and zoom level (desktop) |
| bottom-end | attribution |
| bottom-centre | measure toolbar or draw toolbar, toasts, tile-error banner |
| tour | the first-visit tour card: under the search pill beside the end stack on a narrow screen, and between the search column and the end stack in the panel layout (against the end stack when the step's control is there); hidden with the bottom slots at the full detent, and while the bottom row, lifted above the sheet or a toolbar, would reach it (a short screen with the sheet open, or a tall toolbar or message in the bottom row), and back when there is room. The one thing allowed over it is the credits popover: on a short landscape phone it rises beside the end stack into the card's cell, on the popover layer, both when it shows itself for the first five seconds and when the person opens it later, and it may then cover the card's lower right (step 2's Skip tour at 844 by 390). Closing it with Escape or its button uncovers the card, and the credits must stay readable first |
| map-key | the map key (`MapKey`), in the grid cell above the scale bar, aligned to its bottom edge. `MapChrome` rests it a gap above the bottom row, lifted with that row above the sheet or a toolbar and moved with the scale bar clear of the side panel, from the slot's own measured position, and caps its height at the room between the search pill (or the tour card, while it shows) and that row, so it scrolls inside its own height and never grows over another control. It is not counted in the end stack's height. With less than 48 px of room it gives way: its slot is hidden and `inert` (`data-crowded="true"`), as the tour card does. It is also hidden at the full detent and while the credits popover is open, because the popover grows over this corner and the credits must stay readable; the key returns when the popover closes (so on a page opened with layers on, it appears once the credits' first showing ends) |
| sheet or side panel | one of three. Map options (title "Map options"), from its button, a dropped pin or a tapped feature: basemap, pin, layers (with the open feature card at the top), shapes, save image. Settings (title "Settings and help", so it does not repeat the "Settings" section heading inside it), from its button: settings and help. Directions (title "Directions"), from its button: the directions panel |

Before the app mounts, the server renders a decorative skeleton of this chrome (`ChromeSkeleton`) on the map's background colour: the search pill, the Map options, Measure, Directions (when the host has a routing service, which `ChromeSkeleton` is told with its `directions` prop), Draw shapes (its `draw` prop), Locate me and Settings group, the zoom group where the device has a fine pointer, and the credits button, in their final slots. It reuses the `MapChrome` grid and the real controls' own classes, so the live chrome replaces it in the same boxes with no layout shift (`e2e/skeleton.spec.ts` compares every control's box before and after at 390 by 844 and 1280 by 720). It is `aria-hidden` and `inert`, writes no `style` attribute and uses only tokens. Because the server cannot measure the container, its sheet or side panel layout follows a media query built from the same constants as `chooseLayout`, and its zoom group follows `(hover: hover) and (pointer: fine)`; a stored "show zoom buttons" choice is applied once the app mounts.

Slots use flow layout with gaps from the spacing scale, so neighbours push apart instead of overlapping. On narrow screens the sheet is a bottom sheet with peek, half and full detents. From 768px wide, and on any screen shorter than about 500px, it is a floating side panel on the left. The bottom slots ride above the sheet and hide at the full detent. The end stack is capped at the height `MapChrome` measures for it and scrolls inside that height on a screen too short for every control, with no scrollbar. By default the zoom group yields to a short stack. When the user has chosen to show zoom buttons it stays, and scrolls into view with the rest of the stack. A layout collision test checks every viewport and state.

Map options and Settings open the same sheet or side panel, each at its own sections, so the sheet shows either the Map options group or the Settings group, never both. Settings is always the last button of the main group. Each button is an expanded toggle (`aria-expanded`, `aria-controls` the sheet) that is true only while its own group is the open surface (a pin card in the sheet counts for neither). Pressing a button while the other group is open switches to its group without closing the sheet, and pressing it while its own group is open closes the sheet. Closing returns focus to the button that opened the open group (Map options or Settings), or to the Shapes button of a drawing the sheet was opened over. Shapes and export, a tap on a feature and a dropped pin's card all land on the Map options group, whichever group was open. A sheet opened over Measure or Draw returns to that tool when it closes, with its points or shape kept and focus on the Measure button or the Shapes button.


## Components and accessibility contracts

Native elements first. No tabindex above 0. Every interactive component has an accessible name and a stable `data-testid`, and every floating element has `data-chrome`.

| Component | Contract |
| --- | --- |
| `IconButton` | A `button` named for the action ("Zoom in"). Visible labels are contained in the name. |
| `ControlGroup` | Stacked icon buttons with hairline dividers. A group, not a toolbar. |
| `SearchPill` | `role="search"` with an ARIA 1.2 combobox (`aria-expanded`, `aria-controls`, `aria-activedescendant`) and a "Search" button after it. Typing never searches the geocoder (Nominatim's policy forbids autocomplete): Enter or the button submits, and the results listbox appears after a submit. When the host supplies a suggestion provider, the same listbox (named "Suggestions" until a search is submitted, then "Search results") fills as the person types, once typing pauses and at least three characters are in the box: a suggestion is an option in the same markup as a result, so it takes the same keys, the same tap and the same focus rules, and picking it goes straight to its place and fills the box with its label without suggesting again. Enter with no suggestion highlighted submits the text, Escape closes the list and the next character opens it again, and the count is announced politely ("3 suggestions", "No suggestions"). If the service fails, the list stays closed and one polite message says that suggestions are unavailable and Enter still searches. Arrow keys move through the results, Enter on a highlighted result selects it, and Enter with none highlighted submits. Editing the text hides the old results. Results never take focus. The geocoder adapter starts at most one request a second. Text that is a pair of coordinates (`-26.2041, 28.0473`, `26.2041° S 28.0473° E`, `S26.2041 E28.0473` or degrees, minutes and seconds such as `26°12'14.8"S 28°02'50.3"E`) is answered on submit by the pill itself, with no request: the listbox holds one option named in words, "Coordinates 26.20410° S, 28.04730° E" (the core coordinate formatters), that is selected, announced ("1 result, Coordinates 26.20410° S, 28.04730° E": the label is in the message so a second pair is never silent) and filled into the box exactly as a geocoder result is, and reads back as the same place to about a metre. A plain pair is read latitude first. Each value must carry a mark that says it is degrees: a decimal point with digits after it, or a degree sign (or the word degrees); a bare whole number is not enough, so `12 34`, `E1 6`, `3 4` and `+27 82` go to the geocoder. A minus sign (hyphen, en dash or Unicode minus) starts a value only when no digit or dot touches it from before, so `02-123` and `12-14` are not pairs. A value out of range, a lone number such as a postcode, and anything with text left over go to the geocoder as usual. The Directions panel's place search reads coordinates the same way. |
| `Sheet` | A labelled dialog. Non-modal at peek and half. At full it is modal, the background is `inert`, Tab wraps inside it (with a focus sentinel at each end for Safari, whose Tab skips links and buttons) and Escape closes it. The handle is a button that cycles detents with Enter or Space and moves with the arrow keys. On desktop it is a labelled complementary region. A host may pass a decorative `brand` (a mark and a name): the sheet draws it in a small row above the title, `aria-hidden` and with nothing to focus, so the title stays the accessible name. The bottom sheet leaves the row out at the peek detent. MapCairn passes its cairn mark and name, whose stones take the accent and whose halo takes the map halo role, so it reads on the panel surface in both themes. |
| `MapReadout` | A landmark named "Map scale" holding the scale bar (an image named with the spoken scale) and, on one surface under it, the cursor coordinates and the zoom level, such as "z 12.4". The zoom is the normalised 256 px zoom the address uses, formatted by `formatZoom` with one decimal at most, in `tabular-nums` with no new tokens, and it sits after the coordinates in the same box, so the readout stays one floating element. The drawn "z 12.4" is `aria-hidden` and `user-select: none`; visually hidden text carries "Zoom 12.4" (after a comma when the coordinates come first), so a screen reader and a copy of the text read the zoom once, as "-26.20410, 28.04730, Zoom 12.4". It is plain text, not a live region: the settled zoom is already announced after each zoom, so a change is not spoken. The zoom adds a row at rest, so the `showZoom` prop, when left out, follows the chrome layout: shown in the side panel layout and left out in the bottom sheet layout, where the taller readout would reach the credits popover on a small screen (320 by 568 failed the layout collision test). Pass `showZoom` to decide it yourself. The web host (`AppReadout`) passes it as a fine pointer in the side panel layout (768 px wide or more, or under 500 px tall), and the coordinates need only a fine pointer. A fine-pointer window narrower than that therefore shows the coordinates on hover but no zoom, deliberately; a phone shows neither. |
| `Attribution` | A "Map credits" button with `aria-expanded` and `aria-controls`. The popover is a labelled region with real links and returns focus on close. It shows by itself once the map has started, without taking focus, and collapses on the first map interaction or after five seconds (fading, unless reduced motion is on), because the OpenStreetMap attribution guidelines allow credits to collapse only after they have been shown. It opens above the button, or beside the end stack when the links would have to scroll there (a short landscape phone). |
| `Switch`, `Slider`, `SegmentedControl` | Radix primitives wrapped in our own components, with visible labels and values. |
| Map shape | A `SegmentedControl` named "Map shape" in Settings, between Units and Show zoom buttons, with Flat and Globe (`data-testid` `projection-option-flat` and `projection-option-globe`). Flat is the default and the choice is stored with the other settings. The control behaves as any other segmented control (a radio group, arrow keys move between the two) and announces the change once, politely, through `LiveRegion` ("Map shape: globe"). Choosing Globe redraws the map as a globe at the same view and zoom, still north-up, with the space around it in map-globe-space. A stored globe is known before the app mounts (the pre-paint script marks the root with `data-map-shape="globe"`), so the placeholder is that colour from the first paint and never flashes the flat map's pale ground. Long measure lines and drawn edges follow the great circle on a globe and stop at the horizon; the pin, vertices, handles and directions stops are left out where they are on the far side, and a shape is filled only while all of its outline is in sight. On either shape, a line across the antimeridian is drawn the short way. The scale bar reads the same on both shapes at the same view. |
| `Tooltip` | Supplements a name, never replaces one. Opens on focus and hover, closes on Escape, absent on touch. |
| `LayersSection` | A region named "Layers" with an h4 per group and a list of layers. Each layer is a `Switch` (name and description) with its data cost in words. While it is on: a status line (Loading, "Updated 14:05, 43 shown", the layer's empty text, an error with an icon, words and Try again, or for a tile layer none of whose tiles loaded, the tile layer status below), its controls (segmented, switch, a native date input bounded by `min` and `max`, a date and time control, an opacity slider, a range slider), a legend list named "Key for ..." with the same glyphs as the map, the disclaimer with an icon, and a `details` list of what loaded. Controls whose condition is not met are disabled, not hidden. Loads, empty feeds and failures are announced once each through `LiveRegion`. Above the groups sits "Turn off all layers", a secondary button that shows how many layers are on ("3 on", in `tabular-nums`) and is disabled with `aria-disabled`, never hidden, when none is; each group's heading has "Turn off N in `<group name>`" at its end, shown only while the group has layers on. Neither asks for confirmation, and the buttons stay while the Undo shows. Pressing one turns its layers off in one change (one redraw, one address update) and announces once ("3 layers turned off. Undo available", "1 layer turned off. Undo available"). Below the button the section then shows plain text, "Turned off 3 layers." or "Turned off 2 in `<group name>`.", with an "Undo" button named for what it undoes ("Undo turning off 3 layers", which begins with the visible word); the text is not a live region, so nothing is read twice. Focus stays on "Turn off all layers", with Undo the next stop; a group's button leaves when its group has nothing on, so focus moves to its Undo, and returns to the group's button when Undo is used. Undo stays for 10 seconds (`UNDO_TIMEOUT_MS`) and is replaced by the next batch. The countdown waits while a mouse is over the status and while keyboard focus is inside it, each tracked on its own, and starts again in full when both have left; a tap does not hold it. A layer of the batch that the person turns on again leaves the offer and lowers its count, and the offer ends when none is left. Undo turns the remaining layers back on, with the control values they kept while off, and announces once ("3 layers turned back on"); a layer no longer in the catalogue is skipped. There is no "turn on all", because each layer on is a request to its provider. A host hides the action, the group actions and Undo with `showTurnOffAll={false}` (on `SheetContent` too). The line above the layers is the optional `intro` prop (on `SheetContent` too), "Open data from public providers. Nothing is requested until you turn a layer on." by default, which a host whose layers are not public replaces; an empty string leaves it out. Between that line and the layers sits the catalogue status below. While there are no layers (the catalogue is loading, has failed or is empty) there is no "Turn off all layers" and there are no groups, and a host whose catalogue was ready with no layers when the page opened has no Layers section at all. |
| Catalogue status | Plain text in the Layers section, drawn by `CatalogueStatus` from `DataLayers.catalogue`, in the muted small type of a layer's status line. It is not a live region: `useDataLayers` announces each transition once through `LiveRegion`, and the text is not read a second time. Loading: a loader icon and "Loading layers", and the section is `aria-busy`. Failed: a warning icon and "Layers could not be loaded." in the danger colour, and a secondary "Try again" button. Empty: "No layers are available.", for a list that was awaited. Skipped definitions: "1 layer could not be shown" or "3 layers could not be shown", above the layers. A failed refresh: the warning icon, "Layers could not be updated. Showing the last list." and Try again, with the last list still below. Try again asks the catalogue to load again; it stays in place while it retries, busy (`aria-busy`, a loader in place of its icon) with "Loading layers" in place of the failure, so keyboard focus stays on it. When the catalogue recovers the button goes, and focus moves to the Layers heading if the button had focus or had just been pressed, unless the person has moved it elsewhere (this holds for a refresh the host started as well); when a retry fails again the button keeps focus. There is no general refresh button, and a refresh that only loads shows nothing. Announcements: each state once, when it is entered. A new list is one polite message in a fixed order (layers turned off, layers in the link that are not available, the skipped count, "Layers updated: 1 added, 1 removed.", then "No layers are available." for an empty first list); "Loading layers" is said only while a layer named in the link is waiting; a failed load or refresh is its own assertive message, except that a failed refresh says nothing while the section is hidden. The skipped count is said each time it changes to a number above zero. Each of these is sent with the announcer's `keep` option, so a later message queues behind it and does not replace it, except "Loading layers", which a later message may replace. |
| Feature list | Rows are full-width buttons named by the feature and ", show on map"; a row brings the sheet to half, centres the feature in the part of the map the sheet or side panel leaves free, rings it, scrolls its card into view and opens it (a tap on a point does the same, moving the map only if the point would be hidden), the keyboard and screen-reader equivalent of tapping the point. Sorts are a segmented control; long lists show 50 rows and "Show all". |
| `FeatureCard` | An article named by its heading, which takes focus when a tap on the map opened it. Shows the layer, the colour's words with its glyph, the template lines, an `https` provider link that says it opens in a new tab, the disclaimer, "Show on map" and, for layers with a detail source, "Show affected area" with its cost, "Hide affected area" once shown and Try again on failure. Close is an icon button named "Close card". |
| `DrawToolbar` | A landmark named "Drawing" holding a toolbar named "Draw". A radio group "Shape to draw" (Point, Line, Polygon, Circle), a readout (the shape's name and its measures, such as "Polygon 1, 3 points" and "6.9 ha · 1.21 km"), a refusal or warning with an icon, and a row of buttons: Add point at map centre (Move point to map centre while a point is selected), Undo, Redo, Cancel shape or Delete shape (one button, disabled when neither applies), Shapes and export, and Finish or Done (one button). | `ShapesSection` | A region named "Shapes": a list of drawn shapes (each row a button that selects it, with its measures and `aria-current` on the selected one), Delete selected shape, Delete all shapes, "Import GeoJSON, CSV or WKT" under an Import heading (only when the host supplies a file opener), and Download GeoJSON, Download CSV, Download WKT and Copy link with shapes under an Export heading, each with its outcome beside it in words and an icon. Imported shapes are one undo step, the first is selected, and the map fits to them clear of the sheet or side panel. Above 50 shapes the result adds that a link carries at most 50, so a file is the way to share them. An import that would take the drawing past 1,000 shapes is refused whole, in words. Map region: a focusable region named "Map", described by hidden keyboard instructions. It is `aria-busy` while the style or the basemap's own tiles load, with a loading bar over the map. While the draw tool is open its keys come first: Space, Enter, the arrows with a point selected, the bracket keys, Delete, Backspace, Control or Command with Z, and a staged Escape (leave a point, cancel the shape, drop the selection, then close the tool).

Gesture equivalents: tapping a data point, polygon or line has the layer's list and its "Show on map" rows, and a tap that finds several features has the I key. Saving an image is a button, and importing shapes is a button that opens the browser's own file picker, with no drag and drop to need an equivalent. ## Exempt surfaces

These surfaces hold raw values on purpose and are exempt from the harmony lint (`npm run lint:harmony`, `scripts/harmony`):

- the tokens file (`packages/theme/src/tokens.css.ts`, `tokenValues.ts` and the contrast code and tests)
- the map engine style file (`packages/web/src/adapters/mapEngine.css.ts`), the only place MapLibre selectors (`.maplibregl-*`) and raw engine z-index values may appear
- basemap definitions (`packages/core/src/basemaps`): committed basemap assets and map style definitions are data, and carry their own colours, such as a picker swatch
- tests, fixtures and test support
- `node_modules` and build output

Text baked into basemap tiles comes from the tile source and keeps its own typeface. The inline theme script in `packages/web/src/root.tsx` is a string, so no rule reads it. The scanner's header and `scripts/harmony/config.mjs` list the same surfaces.

One other list exists. `scripts/harmony/allowlist.mjs` holds one-off, justified exceptions (rule, file, snippet and reason), and a stale entry fails the lint.

# Design system

The map is the hero and the chrome recedes. MapCairn is calm, neutral and precise, with grouped controls, a floating search pill and a bottom sheet, in the way people already expect from a good maps app. Light and dark are equally polished. The target is WCAG 2.2 AA, built in from the first component.

Tokens live in `packages/theme/src/tokens.css.ts`. Components may only use tokens, so an off-scale value fails typecheck, and a lint test is the backstop for raw literals.

## Living style guide

`/design` renders every token and every primitive from the real code: colour roles with light and dark hex values and their contrast pairs, the type scale, spacing, radii, elevation, motion, z layers, the Lucide icons the app imports, each component in each state, and a font check that proves IBM Plex Sans is rendering. Open http://localhost:5173/design with `npm run dev`, or http://localhost:4173/design with `npm start` (the e2e build). The route exists only in development and in the `--mode e2e` build (`packages/web/src/designGuideRoutes.ts`); `npm run build` fails if the page's marker reaches the production bundle, and `e2e/design.spec.ts` covers it in the browser.

## Principles

1. One of everything: one family, one accent, one icon set, one stroke, one radius per role.
2. Every control has one owner of its position (`MapChrome`) and one layer (a named z-index).
3. Nothing is conveyed by colour alone.
4. Nothing needs a gesture, a hover or a mouse. Every gesture has a keyboard or single-tap equivalent.

## Tokens

- **Colour roles:** surface, surface-raised, text, text-muted, accent, accent-tint, hairline, danger, scrim, focus-ring, page-background, map-background, map-globe-space. The neutral ramp is OKLCH with a faint cool tint. The accent is one clear blue. Page-background follows the theme and sits behind full pages such as the privacy policy. Map-background is the default basemap's land colour in both themes, so the map region before the map draws matches the map that follows. Map-globe-space is the space around the sphere when the map is a globe, and only then: a cool mid grey in the light theme (`oklch(0.82 0.02 250)`), dark enough that pale land at the edge of the globe still shows and light enough to sit with the light chrome, and a dark blue in the dark theme (`oklch(0.31 0.025 255)`), dark against the dark chrome yet lighter and bluer than the near-black Dark basemap and the deep sea of the Satellite imagery, so their edges show too. A test keeps it at 1.2:1 or more against the land of every basemap the site offers, and the chrome text over it at 4.5:1.
- **Save data:** a switch in Settings, on by default when the browser reports a data saver or a `slow-2g` or `2g` connection (Chrome, Edge and Samsung Internet; iOS has no signal), and a stored choice always wins. While it is on, the picker shows names and a plain colour swatch (the basemap's own `swatch` colour, else the map background token) instead of thumbnails, Streets, Topographic and Satellite, whose tiles are images, carry the note "Uses more data", and a basemap leaves out the style layers it lists in `saveDataOmitLayers`. The SDK's Liberty, which the reference host does not offer, lists its shaded-relief raster layer (`natural_earth`), about a third of the first view's bytes; Bright, the default, Dark and the SDK's Fiord list none, because their styles draw no raster layer. The adapter removes them as each style loads, so no code names a basemap and data layers are drawn again afterwards. Switching it redraws the map once, only for a basemap that lists layers to leave out. Satellite still draws its imagery in Save data mode, because without it the map would be labels on nothing; it never asks for a tile deeper than level 14, where the imagery's real detail ends, and its tiles (14 to 23 KB each over Cape Town at levels 12 to 14, measured 2026-11-11) are a little smaller than the Streets tiles of the same place (22 to 35 KB).
- **Basemap:** Bright is the default in both themes. The basemap never follows the light or dark theme. The picker offers what the host supplies. The reference host offers six, in this order: Bright (the default), Positron, Streets, Topographic, Satellite and Dark, as manual choices like any other. They sit in a grid of three columns, two full rows of three. The SDK defines seven (`BASEMAPS`): Bright, Positron, Streets and Dark from the six, and Liberty, Colorful and Fiord, which a host may offer. Topographic and Satellite are not among them: the reference host defines them itself, Topographic so the SDK does not send every app built on it to a volunteer-run server, and Satellite because its imagery's licence is non-commercial. The reference host builds its own catalogue from a subset of the SDK's list and its own definition, to ask fewer volunteer-run servers for tiles and to keep the picker short. A saved or linked id the host does not offer (`liberty`, `colorful` or `fiord`, the old "auto", or the retired `maptoolkit-dark`) opens on Bright, and a saved value is left alone. Topographic is OpenTopoMap, a free raster map with contour lines and shaded relief, defined by the host and under CC-BY-SA, with its credit in full: OpenStreetMap contributors, SRTM, OpenTopoMap and CC-BY-SA. It reaches zoom 17, as deeper levels return a blank tile. Satellite is a hybrid: EOX's Sentinel-2 cloudless imagery (CC BY-NC-SA 4.0, free for non-commercial use with credit) with the place names, roads and borders of OpenFreeMap Bright over it, because EOX's own labels overlay has no licence of its own. Its credit is shown in full and word for word: "EOxCloudless https://cloudless.eox.at by EOX IT Services GmbH (Contains modified Copernicus Sentinel data 2025)", the licence, a link to EOX::Maps (maps.eox.at), which EOX's tile service asks for, then the OpenFreeMap credits. The imagery's detail ends at zoom 14 and the map stops at 17, where the labels are still useful over the enlarged imagery. Only the style's lines and labels are drawn over the imagery, never its areas. Its appearance is dark, and its swatch is a dark green of the host's own, which is also the ground the map shows before the imagery draws. The WebMCP basemap tool does not offer it, because an agent should not accept a provider's licence on a person's behalf. Dark is OpenFreeMap's neutral dark style, and it asks for no more than the credit text the other OpenFreeMap styles carry. In the SDK, Fiord is OpenFreeMap's blue-toned dark style, and Colorful is VersaTiles' style, from a provider other than OpenFreeMap, which carries its credit text (OpenStreetMap contributors, VersaTiles, ESA WorldCover 2021 and the CC BY 4.0 licence it is under) and nothing else; its land colour is the default's, so it needs no swatch. A basemap with no preview image shows a plain swatch, as every basemap does in Save data mode. A definition may set `swatch`, a hex colour for that tile, so a dark basemap does not look like the pale default: Dark's and Fiord's are their styles' own land colours; Satellite's is a colour of the host's own, not sampled from the imagery. The picker applies it with a custom property set through CSSOM, never an inline `style` attribute. On it, the selected tile's check badge stays legible in both themes (the tick on the accent disc, and the disc or its raised-surface ring against the swatch, at least 3:1), and the name sits below the tile on the sheet. The SDK carries no provider whose licence it would have to accept; a host adds one as data (see `ARCHITECTURE.md`, host-supplied basemaps).
- **Data palette:** the one set of colours data layers draw with, separate from the interface roles. Seven Okabe-Ito categorical colours (without black) and a five-step ordered ramp, light to dark, in `tokenValues.dataPalette`. Definitions name a slot (`vermillion`, `ordinal-3`), never a value; categories must use categorical slots and steps ordinal ones. Every marker has a dark edge inside a white halo (`tokenValues.dataMarker`), the same on the map and in the legend, so the pale steps show on a light map and the dark ones on a dark surface; contrast tests cover both. Validation refuses a colour rule with no shape, size or words beside it.
- **Surfaces:** translucent with backdrop blur, with an opaque fallback and the `-webkit-` prefix. `prefers-contrast: more` and `prefers-reduced-transparency` make them opaque and remove blur. Contrast is computed over the worst-case backdrops (pure white and pure black map) and over the default basemap's land colour, because a dark theme no longer means a dark map.
- **Spacing:** 4, 8, 12, 16, 24, 32. Screen inset is 12.
- **Radii:** pill 24, sheet 20, control and card 14, inner 10. Fully circular elements use 50%.
- **Elevation:** two shadows, floating and sheet, each with light and dark values. No borders on floating elements. Hairlines only inside lists and between grouped controls.
- **Type:** IBM Plex Sans only, self-hosted through Fontsource (variable, Latin and Latin Extended), weights 400 and 600. Sizes 13, 15, 17 and 22, defined in rem with a line height and tracking each. Nothing below 13px. Numbers use `tabular-nums`. Inputs are 17px, never below 16px. The fallback stack is `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`, which also covers non-Latin place names.
- **Size:** controls are 48px minimum, targets never below 44px, switches and slider thumbs included (their hit area is larger than what they draw), with at least 8px between neighbours.
- **Icons:** `lucide-react` only, imported by name, 24px, one stroke-width token, through the `Icon` component.
- **Focus ring:** two tones (an inner surface ring and an outer ring, 2px each) so it shows on any basemap. Every interactive element and the focused map use it.
- **Motion:** 120, 200 and 320ms, one easing curve, one spring for the sheet. Only transform and opacity animate. `prefers-reduced-motion` turns motion off, including MapLibre's own animation.
- **Z layers, bottom to top:** map, mapOverlay, chrome, chromeRaised, sheet, toolbar, popover, toast. Components name a layer and never write a number. The tokens file and the map engine style file are the only places raw z-index values may appear.

## Layout and slots

`MapChrome` owns the position of everything floating over the map. It is `pointer-events: none`, and each slot's contents are `pointer-events: auto`.

| Slot | Contents |
| --- | --- |
| top-start | search pill |
| end-stack | compass (when the map is rotated), main control group (Map options, Measure, Directions when the host has a routing service, Draw shapes, Locate me, Settings), zoom control group (when shown) |
| bottom-start | scale readout, cursor coordinates (desktop) |
| bottom-end | attribution |
| bottom-centre | measure toolbar or draw toolbar, toasts, tile-error banner |
| tour | the first-visit tour card: under the search pill beside the end stack on a narrow screen, and between the search column and the end stack in the panel layout (against the end stack when the step's control is there); hidden with the bottom slots at the full detent, and while the bottom row, lifted above the sheet or a toolbar, would reach it (a short screen with the sheet open, or a tall toolbar or message in the bottom row), and back when there is room. The one thing allowed over it is the credits popover: on a short landscape phone it rises beside the end stack into the card's cell, on the popover layer, both when it shows itself for the first five seconds and when the person opens it later, and it may then cover the card's lower right (step 2's Skip tour at 844 by 390). Closing it with Escape or its button uncovers the card, and the credits must stay readable first |
| sheet or side panel | one of three. Map options (title "Map options"), from its button, a dropped pin or a tapped feature: basemap, pin, layers (with the open feature card at the top), shapes, save image. Settings (title "Settings and help", so it does not repeat the "Settings" section heading inside it), from its button: settings and help. Directions (title "Directions"), from its button: the directions panel |

Before the app mounts, the server renders a decorative skeleton of this chrome (`ChromeSkeleton`) on the map's background colour: the search pill, the Map options, Measure, Directions (when the host has a routing service, which `ChromeSkeleton` is told with its `directions` prop), Draw shapes (its `draw` prop), Locate me and Settings group, the zoom group where the device has a fine pointer, and the credits button, in their final slots. It reuses the `MapChrome` grid and the real controls' own classes, so the live chrome replaces it in the same boxes with no layout shift (`e2e/skeleton.spec.ts` compares every control's box before and after at 390 by 844 and 1280 by 720). It is `aria-hidden` and `inert`, writes no `style` attribute and uses only tokens. Because the server cannot measure the container, its sheet or side panel layout follows a media query built from the same constants as `chooseLayout`, and its zoom group follows `(hover: hover) and (pointer: fine)`; a stored "show zoom buttons" choice is applied once the app mounts.

Slots use flow layout with gaps from the spacing scale, so neighbours push apart instead of overlapping. On narrow screens the sheet is a bottom sheet with peek, half and full detents. From 768px wide, and on any screen shorter than about 500px, it is a floating side panel on the left. The bottom slots ride above the sheet and hide at the full detent. The end stack is capped at the height `MapChrome` measures for it and scrolls inside that height on a screen too short for every control, with no scrollbar. By default the zoom group yields to a short stack. When the user has chosen to show zoom buttons it stays, and scrolls into view with the rest of the stack. A layout collision test checks every viewport and state.

Map options and Settings open the same sheet or side panel, each at its own sections, so the sheet shows either the Map options group or the Settings group, never both. Settings is always the last button of the main group. Each button is an expanded toggle (`aria-expanded`, `aria-controls` the sheet) that is true only while its own group is the open surface (a pin card in the sheet counts for neither). Pressing a button while the other group is open switches to its group without closing the sheet, and pressing it while its own group is open closes the sheet. Closing returns focus to the button that opened the open group (Map options or Settings), or to the Shapes button of a drawing the sheet was opened over. Shapes and export, a tap on a feature and a dropped pin's card all land on the Map options group, whichever group was open. A sheet opened over Measure or Draw returns to that tool when it closes, with its points or shape kept and focus on the Measure button or the Shapes button.


## Components and accessibility contracts

Native elements first. No tabindex above 0. Every interactive component has an accessible name and a stable `data-testid`, and every floating element has `data-chrome`.

| Component | Contract |
| --- | --- |
| `IconButton` | A `button` named for the action ("Zoom in"). Visible labels are contained in the name. |
| `ControlGroup` | Stacked icon buttons with hairline dividers. A group, not a toolbar. |
| `SearchPill` | `role="search"` with an ARIA 1.2 combobox (`aria-expanded`, `aria-controls`, `aria-activedescendant`) and a "Search" button after it. Typing never searches (Nominatim's policy forbids autocomplete): Enter or the button submits, and the results listbox appears after a submit. Arrow keys move through the results, Enter on a highlighted result selects it, and Enter with none highlighted submits. Editing the text hides the old results. Results never take focus. The geocoder adapter starts at most one request a second. Text that is a pair of coordinates (`-26.2041, 28.0473`, `26.2041° S 28.0473° E`, `S26.2041 E28.0473` or degrees, minutes and seconds such as `26°12'14.8"S 28°02'50.3"E`) is answered on submit by the pill itself, with no request: the listbox holds one option named in words, "Coordinates 26.20410° S, 28.04730° E" (the core coordinate formatters), that is selected, announced ("1 result, Coordinates 26.20410° S, 28.04730° E": the label is in the message so a second pair is never silent) and filled into the box exactly as a geocoder result is, and reads back as the same place to about a metre. A plain pair is read latitude first. Each value must carry a mark that says it is degrees: a decimal point with digits after it, or a degree sign (or the word degrees); a bare whole number is not enough, so `12 34`, `E1 6`, `3 4` and `+27 82` go to the geocoder. A minus sign (hyphen, en dash or Unicode minus) starts a value only when no digit or dot touches it from before, so `02-123` and `12-14` are not pairs. A value out of range, a lone number such as a postcode, and anything with text left over go to the geocoder as usual. The Directions panel's place search reads coordinates the same way. |

It opens above the button, or beside the end stack when the links would have to scroll there (a short landscape phone). |

| `LayersSection` | A region named "Layers" with an h4 per group and a list of layers. Each layer is a `Switch` (name and description) with its data cost in words. Controls whose condition is not met are disabled, not hidden. Loads, empty feeds and failures are announced once each through `LiveRegion`. |
| Feature list | Rows are full-width buttons named by the feature and ", show on map"; a row brings the sheet to half, centres the feature in the part of the map the sheet or side panel leaves free, rings it, scrolls its card into view and opens it (a tap on a point does the same, moving the map only if the point would be hidden), the keyboard and screen-reader equivalent of tapping the point. Sorts are a segmented control; long lists show 50 rows and "Show all". |
| `FeatureCard` | An article named by its heading, which takes focus when a tap on the map opened it. Shows the layer, the colour's words with its glyph, the template lines, an `https` provider link that says it opens in a new tab, the disclaimer, "Show on map" and, for layers with a detail source, "Show affected area" with its cost, "Hide affected area" once shown and Try again on failure. Close is an icon button named "Close card". |

| `VisuallyHidden` | The one way to provide screen-reader-only text. |

Map region: a focusable region named "Map", described by hidden keyboard instructions. Arrow keys pan, plus and minus zoom, Shift with left and right arrows rotates, Home or 0 resets north, P drops a pin, I lists the features at the centre of the map, Escape closes the active surface. While the draw tool is open its keys come first: Space, Enter, the arrows with a point selected, the bracket keys, Delete, Backspace, Control or Command with Z, and a staged Escape (leave a point, cancel the shape, drop the selection, then close the tool).

Gesture equivalents: tapping a data point, polygon or line has the layer's list and its "Show on map" rows, and a tap that finds several features has the I key. Saving an image is a button, and importing shapes is a button that opens the browser's own file picker, with no drag and drop to need an equivalent. Drawing has Add point at map centre and the Space key. Selecting a point has Previous point, Next point and the bracket keys. Dragging a point has the arrow keys (Shift for more) and Move point to map centre. Tapping a midpoint handle to add a vertex has Add point after this one at map centre, and dragging a circle's radius handle has the radius buttons. Finish has Enter, Cancel has Escape and Remove point has Delete or Backspace. Long-press pin has "Drop pin at map centre" and the P key. Pinch and double-tap have the zoom buttons and +/-. Rotation has Shift with left and right arrows and the compass. Sheet drag has the handle button. Measure taps have "Add point at map centre". Directions stop taps have "Add stop at map centre", "Add dropped pin" and a place search, and any drag of a stop has the Move and Remove buttons.

## Exempt surfaces

These surfaces hold raw values on purpose and are exempt from the harmony lint (`npm run lint:harmony`, `scripts/harmony`):

- the tokens file (`packages/theme/src/tokens.css.ts`, `tokenValues.ts` and the contrast code and tests)
- the map engine style file (`packages/web/src/adapters/mapEngine.css.ts`), the only place MapLibre selectors (`.maplibregl-*`) and raw engine z-index values may appear
- basemap definitions (`packages/core/src/basemaps`): committed basemap assets and map style definitions are data, and carry their own colours, such as a picker swatch
- tests, fixtures and test support
- `node_modules` and build output

Text baked into basemap tiles comes from the tile source and keeps its own typeface. The inline theme script in `packages/web/src/root.tsx` is a string, so no rule reads it. The scanner's header and `scripts/harmony/config.mjs` list the same surfaces.

One other list exists. `scripts/harmony/allowlist.mjs` holds one-off, justified exceptions (rule, file, snippet and reason), and a stale entry fails the lint.

# Using the reference site

What the reference host offers for searching, saving the map, reading the layer key, turning layers off and drawing, and how each works from the keyboard and a pointer.

## Search by place name or coordinates

As you type, the search box suggests places once you pause after three or more characters. Choose one with the arrow keys and Enter, or tap it, and the map goes straight to it. The suggestions come from the Photon service, so the text you have typed so far is sent there as you type; the privacy page says so. A screen reader hears how many suggestions there are. If the service is unavailable, the box says so once and stops suggesting for a while.

The search box finds a place by name through the geocoder when you press Enter or the Search button, with or without a suggestion highlighted, and that works when suggestions do not. It also takes a pair of coordinates, and answers that one itself, in the browser, with no request to the geocoder: a single result named "Coordinates 26.20410° S, 28.04730° E" that you choose like any other result. It reads:

- decimal degrees, latitude first: `-26.2041, 28.0473` or `-26.2041 28.0473`. Every value needs a decimal point with digits after it, or a degree sign or the word degrees
- hemisphere letters (or the words north, south, east and west) before or after a value, in either order: `26.2041S 28.0473E`, `S26.2041 E28.0473`, `28.0473 E, 26.2041 S`
- degrees, minutes and seconds with the usual symbols or words: `26°12'14.8"S 28°02'50.3"E`, `26 degrees 12 minutes 14.8 seconds south, 28 degrees 2 minutes 50.3 seconds east`

A comma is only ever a separator, never a decimal mark, and a negative sign (hyphen, en dash or Unicode minus) cannot be mixed with a hemisphere letter. A bare whole number is not a coordinate, so `12 34`, `3 4`, `+27 82` and `E1 6` are searched as place names; so are `02-123` and `12-14`, because a minus sign that touches a number before it is not the start of a negative value. Text that is out of range (latitude beyond 90, longitude beyond 180), a lone number such as a postcode, or anything with extra text is treated as a place name and searched as usual. Showing a coordinate result sends nothing to the geocoder, but the map loads tiles for that area as it does for any move. The parser is `parseCoordinates` in `@mapcairn/core`, and `useSearch` uses it, so the Directions panel's place search reads coordinates too.

## Save an image and choose between features

The sheet's "Save image" button saves a PNG of the map with its layers, any drawn shapes and credits, made in the browser from what the map has already loaded. A tap that finds several features opens a list, and the `I` key opens the same list for the centre of the map. Neither needs configuration.

## Read the key on the map

While a layer that has a key is on, its key shows on the map, above the scale bar, so you can read what its colours and shapes mean without opening Layers. Each layer has a block: its name, then one line for each colour or shape with its words. A layer with no key, such as the imagery layers, has no block, and with no keyed layer on there is no key at all.

A phone, held either way up, starts the key as a small chip, "Key, 3 layers", with the symbols of a few of the layers; a tablet or a desktop starts it open. That is decided when the key first appears, so turning the phone does not change it. Choose the chevron to shrink the key to the chip, and the chip to open it again; the button is named "Map key, 3 layers" either way. The key remembers your choice until you reload the page; it is not stored between visits and puts nothing in the address. When many layers are on, the key scrolls inside its own height. It steps aside while the map credits are open, and when something else leaves too little room above the scale bar.

## Turn layers off

In the Layers section, "Turn off all layers" at the top turns every layer off at once, and shows how many are on ("3 on"); it is greyed out when none is. Each group heading has the same action for its own layers, such as "Turn off 2 in Fires", while any of them is on. There is no confirmation. Below the button, "Turned off 3 layers." appears with an Undo, which turns those layers back on; their settings stay as they were, because a layer keeps its settings while it is off. A layer you turn on again yourself leaves the Undo, and the count drops. The Undo stays for ten seconds, and waits while a mouse is over it or it has keyboard focus. There is no "turn on all", because each layer you turn on asks its provider for data.

## Draw and export shapes

Choose **Draw shapes** in the control group beside the map. Pick Point, Line, Polygon or Circle, then tap the map to place points, or use **Add point at map centre** (or Space) after panning. A circle takes its centre first and its radius from the second tap. **Finish** (or Enter) closes the shape; a polygon needs three points and no crossing edges. Tap a shape's edge or choose it in the **Shapes** list to edit it: drag a point, drag a small midpoint handle to add one, or select a point with Previous point and Next point and move it with the arrow keys. Undo and Redo cover every edit.

**Shapes and export** opens the list. **Download GeoJSON**, **Download CSV** and **Download WKT** build a file on your device from the finished shapes (the CSV has `id`, `type`, `area_m2`, `length_m`, the GeoJSON geometry as text, and then `radius_m`, `centre_lng` and `centre_lat`, the last three filled for a circle; these three columns were added at the end, and a CSV from before them still imports, with a circle as its polygon). The WKT file has one geometry to a line, longitude first, with a circle written as its polygon. **Import GeoJSON, CSV or WKT** reads a file on your device, nothing is uploaded, and adds its points, lines, polygons and circles to the shapes as one undo step, then fits the map to them. It reads GeoJSON (a collection, a feature or a geometry, with Multi geometries split into one shape each and a polygon's holes left out), the CSV the export writes, so an exported file comes back as the same shapes, and WKT (one geometry or several, a line each or any layout, longitude then latitude, or the cells of a CSV column headed `wkt` in a comma-delimited file). WKT is read longitude first and the axis order cannot yet be chosen on the site (issue #84), so a file that writes latitude first imports in the wrong place. An EWKT prefix of `SRID=4326;`, as database exports write, is read and dropped. Any other SRID refuses a whole text file with a message naming it; in a CSV column only the row with that cell is skipped, and the result counts it as "in a coordinate system other than SRID 4326". WKT text that cannot be read, or that holds a measure or a curve, is refused whole with the reader's position in the message, and nothing in it is imported; in a CSV only the row with that cell is skipped. A file of more than 1 MB, 500 shapes or 10,000 points is refused, and so is an import that would take the drawing past 1,000 shapes, and a shape with crossing edges, too few points or a position outside the world is skipped; the result says which and how many. Shapes are not stored and are not in the address bar. **Copy link with shapes** copies a link that carries them in a compact encoding of up to 2,000 characters; anyone who opens it sees the shapes, and moving the map in their window drops them from the address. In code, the pure rules are in `packages/core/src/draw`, the state hook is `useDraw`, the toolbar and overlay are `DrawToolbar` and `DrawOverlay` in `@mapcairn/map`, the import is `parseShapeFile` in core with the `FileOpener` port, and a host adds drawing by passing `onDraw` to `EndStack` and `draw` to `SheetContent`.

# `@mapcairn/theme`

MapCairn's design tokens, built with [vanilla-extract](https://vanilla-extract.style/). It has no dependency on another MapCairn package, a map engine or React. [`DESIGN.md`](../../DESIGN.md) describes the system and the rules for using it.

## Exports

| Export                                                          | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tokens`                                                        | The token contract: `tokens.color.*`, `shadow`, `effect`, `space`, `radius`, `type`, `size`, `focus`, `motion` and `z`. Each is a typed CSS variable reference, so a typo in a `.css.ts` file is a type error. The values and the light and dark switching are defined in `src/tokens.css.ts`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `focusRing`, `blur`, `surfaceBlurStyle`, `surfaceBlurSupported` | Shared style fragments: the two-tone focus ring, and translucent surfaces with an opaque fallback.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `zLayer(name)`                                                  | The z-index variable for a named layer (map, mapOverlay, chrome, chromeRaised, sheet, toolbar, popover, toast). Components name a layer and never write a number.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `mapOverlayTokens`                                              | Colours for everything drawn over the map: pin, measure line and fill, accuracy circle, scale bar and tile-error banner.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `checkThemeContrast(override)`                                  | Checks a proposed partial colour override (14 interface roles, light and dark) against WCAG 2.2 AA over the worst-case map backdrops and returns the ratio, the minimum and the backdrop for each pair, as data. It never throws and does not accept or refuse a theme. Only hex, `rgb()`/`rgba()` and `oklch()` colours are supported; named colours, `hsl()`, `oklab()` and `color()` are reported as unparseable. A wrong-shaped override or an unknown key returns `invalid` entries (with `theme: null` and the reasons `malformed`, `unknown-key` or `unreadable`), and `passes` is false whenever anything is invalid. It checks only; `createThemeStylesheet` applies an override. Types: `ThemeOverride`, `ThemeColours`, `ThemeContrastCheck`, `ContrastFinding`, `InvalidColour`, `InvalidColourReason`, and the names they use: `ThemeColourRole`, `ContrastBackground`, `BackdropName`, `PairKind`, `ThemeName`.                                                                               |
| `createThemeStylesheet(override, { scope })`                    | Turns a colour override into a stylesheet scoped to a selector the host owns (`:root`, `#id` or `.class`), or refuses. A theme below WCAG 2.2 AA, an unusable colour or an unusable scope returns `{ ok: false, css: undefined, findings, invalid, invalidScope }` and no CSS. Otherwise it returns `{ ok: true, css, findings }`: serve `css` as a same-origin file and link it after the SDK's stylesheets. The rules are written inside `(not (prefers-contrast: more))` and `(not (forced-colors: active))`, so high-contrast and forced-colours users keep the SDK's values, and it adds an opaque surface for browsers without `backdrop-filter` and for reduced transparency. Colours only; page, map and data roles are not overridable. The custom property names it writes are generated and private, and match the SDK's stylesheet only for the same installed version of this package. Types: `ThemeStylesheet`, `ThemeStylesheetCreated`, `ThemeStylesheetRefused`, `ThemeStylesheetOptions`. |
| `tokenValues`                                                   | The raw values (colour roles for both themes, spacing, radii, type scale, motion, z layers). Used by tests and the contrast checks, not by components.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

The token set and the contrast checks live in `src/tokens.css.ts`, `src/tokenValues.ts` and `src/contrast.ts`. The contrast tests compute every text and boundary pairing over the worst-case map backdrops in both themes.

```ts
// Button.css.ts
import { focusRing, tokens } from "@mapcairn/theme";
import { style } from "@vanilla-extract/css";

export const button = style({
  backgroundColor: tokens.color.surfaceRaised,
  borderRadius: tokens.radius.control,
  ":focus-visible": focusRing,
});
```

## Using it in a host app

`npm run build:sdk` builds this package to `dist`: JavaScript, declarations and the compiled `tokens.css`. The source stays in this repository, behind the `@mapcairn/source` export condition, which this repository's Vite configs and `tsconfig.base.json` turn on; the published package holds `dist` only. A host that resolves that condition registers `vanillaExtractPlugin()` from `@vanilla-extract/vite-plugin` in its Vite config; an app that uses `dist` needs no plugin. The JavaScript is side-effect free (`sideEffects` names only `.css` files), so from source the token stylesheet reaches the page only through an import that is used, as `packages/web/src/global.css.ts` does with `tokens` and `focusRing`. A consumer of `dist` gets the tokens only by importing `@mapcairn/theme/tokens.css`.

## What doesn't belong here

- App-specific values, copy or storage keys.
- Raw colour, size or z-index literals outside `tokens.css.ts` and `tokenValues.ts`. The harmony scanner enforces this.

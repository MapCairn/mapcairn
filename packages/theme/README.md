# `@mapcairn/theme`

MapCairn's design tokens: typed references to CSS custom properties for colour, space, type, radius, shadow, motion and layering, with a light and a dark theme. Use it to style your own components so they match MapCairn's interface, or to check the contrast of a theme of your own. It is built with [vanilla-extract](https://vanilla-extract.style/) and has no dependency on another MapCairn package, a map engine or React.

Most apps should install [`@mapcairn/sdk`](https://github.com/MapCairn/mapcairn/tree/main/packages/sdk) instead: one install, one import and one stylesheet for the whole SDK, which re-exports this package. Install `@mapcairn/theme` on its own as the advanced option, for a host that wants fewer dependencies.

**Status:** pre-1.0. While the version starts with `0.`, a minor release (the middle number) can contain a breaking change to the public API and a patch release (the last number) is not meant to, so a `^0.1.0` range takes patch releases but not the next minor release. The [changelog](https://github.com/MapCairn/mapcairn/blob/main/CHANGELOG.md) names each breaking change the release finds, and [what counts as the public API](https://mapcairn.timothybrits.co.za/docs/guides/public-api/) says what is covered.

## Install

```bash
npm install @mapcairn/theme
pnpm add @mapcairn/theme
yarn add @mapcairn/theme
```

The package is ESM only: it has no `main` field and no CommonJS build. A TypeScript project needs `moduleResolution` set to `node16`, `nodenext` or `bundler`; `node10` is not supported.

## Usage

Import the token stylesheet once, in your entry module. It defines the custom properties for both themes. The `@mapcairn/map` components also need `@mapcairn/map/styles.css`, shown in the [`@mapcairn/map` README](https://github.com/MapCairn/mapcairn/tree/main/packages/map#set-up).

```ts
import "@mapcairn/theme/tokens.css";
import { tokens } from "@mapcairn/theme";

Object.assign(document.body.style, {
  fontFamily: tokens.type.family,
  fontSize: tokens.type.body.size,
  lineHeight: tokens.type.body.lineHeight,
  color: tokens.color.text,
  backgroundColor: tokens.color.pageBackground,
});
```

Each value in `tokens` is a string of the form `var(--…)`, so it works in any style object. The package needs no vanilla-extract plugin: `dist` holds plain JavaScript and the compiled `tokens.css`. The generated custom property names are private and can change in any release, so use `tokens` and never write the names into a stylesheet of your own. [How the CSS ships](https://github.com/MapCairn/mapcairn/blob/main/DESIGN.md#how-the-css-ships) says what is and is not settled.

## What it exports

| Export                                                          | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tokens`                                                        | The token contract: `tokens.color.*`, `shadow`, `effect`, `space`, `radius`, `type`, `size`, `focus`, `motion` and `z`. Each is a typed CSS variable reference, so a typo in a `.css.ts` file is a type error. The values and the light and dark switching are defined in `src/tokens.css.ts`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `focusRing`, `blur`, `surfaceBlurStyle`, `surfaceBlurSupported` | Shared style fragments: the two-tone focus ring, and translucent surfaces with an opaque fallback.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `zLayer(name)`                                                  | The z-index variable for a named layer (map, mapOverlay, chrome, chromeRaised, sheet, toolbar, popover, toast). Components name a layer and never write a number.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `mapOverlayTokens`                                              | Colours for everything drawn over the map: pin, measure line and fill, accuracy circle, scale bar and tile-error banner.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `checkThemeContrast(override)`                                  | Checks a proposed partial colour override (14 interface roles, light and dark) against WCAG 2.2 AA over the worst-case map backdrops and returns the ratio, the minimum and the backdrop for each pair, as data. It never throws and does not accept or refuse a theme. Only hex, `rgb()`/`rgba()` and `oklch()` colours are supported; named colours, `hsl()`, `oklab()` and `color()` are reported as unparseable. A wrong-shaped override or an unknown key returns `invalid` entries (with `theme: null` and the reasons `malformed`, `unknown-key` or `unreadable`), and `passes` is false whenever anything is invalid. It checks only; `createThemeStylesheet` applies an override. Types: `ThemeOverride`, `ThemeColours`, `ThemeContrastCheck`, `ContrastFinding`, `InvalidColour`, `InvalidColourReason`, and the names they use: `ThemeColourRole`, `ContrastBackground`, `BackdropName`, `PairKind`, `ThemeName`.                                                                                                                                                                                   |
| `createThemeStylesheet(override, { scope })`                    | Turns a colour override into a stylesheet scoped to a selector the host owns (`:root`, `#id` or `.class`), or refuses. A theme below WCAG 2.2 AA, an unusable colour or an unusable scope returns `{ ok: false, css: undefined, findings, invalid, invalidScope }` and no CSS. Otherwise it returns `{ ok: true, css, findings }`: serve `css` as a same-origin file and link it after the SDK's stylesheets. The rules are written inside `(not (prefers-contrast: more))` and `(not (forced-colors: active))`, so high-contrast and forced-colours users keep the SDK's values, and it adds an opaque surface for browsers without `backdrop-filter` and for reduced transparency. Colours only; page, map and data roles are not overridable. The scope is matched as a descendant of `:root`, so a class on `<html>` does nothing (use `:root`). The custom property names it writes are generated and private, and match the SDK's stylesheet only for the same installed version of this package. Types: `ThemeStylesheet`, `ThemeStylesheetCreated`, `ThemeStylesheetRefused`, `ThemeStylesheetOptions`. |
| `tokenValues`                                                   | The raw values (colour roles for both themes, spacing, radii, type scale, motion, z layers). Used by tests and the contrast checks, not by components.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

In the repository, the token set and the contrast checks live in `src/tokens.css.ts`, `src/tokenValues.ts` and `src/contrast.ts`. The contrast tests compute every text and boundary pairing over the worst-case map backdrops in both themes.

[`DESIGN.md`](https://github.com/MapCairn/mapcairn/blob/main/DESIGN.md) describes the design system and the rules for using it.

# `@mapcairn/core`

The ports, pure logic and basemap definitions of MapCairn. It has no dependency on another MapCairn package, React, a map engine or a browser global, and it never reads the clock. The only runtime dependencies are `@turf` maths libraries.

See [`ARCHITECTURE.md`](../../ARCHITECTURE.md) for how core fits with the other packages and the dependency rules that `npm run lint` enforces.

## Exports

Everything is exported from `@mapcairn/core`, apart from the contract suites, which come from `@mapcairn/core/contracts`. The suites import `vitest`, an optional peer dependency: install it only if you run them.

| Area | Source | What it holds |
|---|---|---|
| Ports | `src/ports` | Types only, apart from small error classes. `Services` (the bundle the app is built from), `MapAdapter` and `MapAdapterFactory`, `SearchProvider`, `SuggestionProvider` (optional: places as the person types, with no provider built in), `RoutingProvider` (optional: routes and travel-time areas, with no provider built in), `LocationProvider`, `SettingsStore`, `ClipboardPort`, `FileSaver`, `FileOpener` (optional: reads a file the person picks, for import), `UrlState`, `ThemeSource`, `DevicePreferences`, `LayerCatalogue` (the layers on offer, as a store that can load after the app starts), `LayerSource`, `FeatureSelection` (optional: the features a person has picked, as a synchronous store with a limit, which a host supplies; `MemoryFeatureSelection` is the in-memory one, with `DEFAULT_SELECTION_LIMIT`), `BasemapDefinition`, the geometry types (`LatLng`, `Bounds`, `ViewState`, `PixelPoint`) and the typed errors (`SearchError`, `LocationError`, `LayerError`, `RoutingError`, `MapEngineError`, `MapImageExportError`, `FileOpenError`, `PortAbortError`). |
| Basemaps | `src/basemaps` | `BASEMAPS` (OpenFreeMap Bright, Liberty, Positron, Fiord and Dark, VersaTiles Colorful and OpenStreetMap Streets: seven in all), `getBasemap`, `createBasemapCatalogue` with `BUILT_IN_BASEMAP_CATALOGUE` (the basemaps a host offers, passed as the optional `Services.basemaps`), `DEFAULT_BASEMAP_ID` (Bright, in both themes), `DEFAULT_BASEMAP_BACKGROUND` (its land colour, painted before the map draws), `buildAttribution`, and `usesMoreData` (true for a basemap drawn from image tiles: a `raster` source, or a `hybrid` source, which puts a vector style's lines and labels over image tiles). A definition may set `nonCommercial` when its provider's licence allows only non-commercial use; `BASEMAPS` holds none, and a host must keep such a basemap out of any tool an agent can call. The only place that names a tile source or a credit. A definition's optional `thumbnail` is a root-relative path the host serves (if the image fails to load, the picker shows the swatch). The SDK's own definitions name none, so a host that serves no previews shows a swatch for each, and a host that does adds the paths to the definitions it offers. |
| Fakes | `src/fakes` | In-memory implementations of every port (`FakeMapAdapter`, `FakeSearchProvider`, `MemorySettingsStore` and so on) and `createFakeServices()`, for unit tests that run with no browser, WebGL or network. `pngHeader` and `readPngSize` build and read the start of a PNG (`readPngSize` gives `undefined` for bytes that are not one), so a test can check the size of an image a fake or an adapter made. |
| Contract suites | `src/contracts` (`@mapcairn/core/contracts`) | One shared suite per port, run against the fake and the real adapter, so they cannot drift apart. `PORT_REGISTRY` lists them. |
| Surface and sheet | `src/surface`, `src/sheet`, `src/layout` | The surface state machine (`surfaceReducer` and its actions), sheet detents and snapping, and the chrome layout rules. |
| Map maths | `src/zoom`, `src/scale`, `src/format`, `src/units`, `src/spatial` | Zoom conversion (the app uses 256 px tile zoom, the engine zoom is one lower), metres per pixel, the scale bar, coordinate and number formatting, unit conversion, and line distance and polygon area measurement (`measureLineDistance`, `measurePolygonArea`), the bounds of a set of points (`boundsOfPoints`) and rounding a position before a reverse lookup (`roundForLookup`). |
| Coordinates | `src/coordinates` | `parseCoordinates`, which reads typed coordinates (decimal degrees, degrees minutes and seconds, hemisphere letters) in linear time and refuses anything ambiguous or out of range, and `coordinateSearchResult`, which turns such text into one `SearchResult` so a search box can answer it without a geocoder request. |
| Geometry | `src/geometry` | Pure helpers over GeoJSON geometries and features: `buffer` (metres, with a step count), `union`, `intersect`, `difference`, `simplify` (tolerance in metres), `centroid`, `boundingBox` with `boundingBoxToBounds`, `pointInPolygon` (holes and multipolygons) and `geometryLength` and `geometryArea` (built on the measurement helpers). `wgs84ToWebMercator` and `webMercatorToWgs84` convert between EPSG:4326 and EPSG:3857. `parseWkt` and `formatWkt` read and write Well-Known Text with a hand-written tokenizer, so hostile text takes linear time; the reader takes longitude then latitude unless given `axisOrder: "lat-lng"`, accepts an EWKT `SRID=4326;` prefix at the start of a geometry and refuses any other SRID with an `UnsupportedSridError` (an `unsupported` `GeometryError` that carries the `srid`), and `readWktSequence` reads several geometries one after another without checking their shapes, for a caller that applies its own rules, and `startsLikeWkt` says whether a text starts with a WKT type name or an SRID prefix. Every helper checks its input and throws a `GeometryError` (`invalid`, `empty` or `unsupported`). Longitude is a flat axis: a buffer that would cross the antimeridian or enclose a pole is refused, and a shape that crosses 180 degrees must be split first. The geometry helpers (WKT, Web Mercator conversion, union, intersect, difference, simplify, centroid, point in polygon, bounding box and length) are deliberate SDK surface for hosts that need them. The reference host does not use most of them yet. |
| Keyboard, announcements and URL | `src/keyboard`, `src/announce`, `src/urlHash` | The map key bindings and their help text, the announcement strings for screen readers, and `#map=` parsing and serialising. |
| Image export | `src/imageExport` | `planRequestedImage`, which checks a request for an image at a size, pixel ratio and view (`MapImageOptions`), fills in what it leaves out from the map on screen, rounds the size to whole CSS pixels, clamps the view on screen, and refuses one that is not valid (a box across the antimeridian is not yet, nor is a box on a globe) or over `MAX_IMAGE_SIDE_PX` or `MAX_IMAGE_PIXELS`, so the fake and every adapter refuse the same requests. |
| Draw | `src/draw` | The draw tool's pure reducer, shape rules and measures, and its text formats: `shapesToGeoJson`, `shapesToCsv` and `shapesToWkt` write shapes, and `parseShapeFile` reads GeoJSON, WKT (as text or a CSV column headed `wkt`, with `wktAxisOrder` for latitude-first text) and the CSV the draw tool wrote. The import never throws and is bounded in size, nesting, shapes and points. |
| Theme resolution | `src/theme` | `resolveTheme`, `parseThemeChoice` and `buildThemeBootstrapScript`, with the storage key and `<meta name="theme-color">` values. |
| Layers | `src/layers` | `createStaticLayerCatalogue`, which validates a host's layer definitions when the app starts and is ready on the first render, `createRuntimeLayerCatalogue`, which loads them through a `load` function the host writes (on the first subscription, once, with `dispose()` for teardown), `partitionDefinitions`, which sorts untrusted definitions into valid ones and skipped ones with their problems, and `emptyLayerCatalogue`, a catalogue with no layers for a host that supplies none, so the sheet hides its Layers section. `readyLayers` gives the layers of a ready state, and none for any other. A raster tile layer may carry an `identify` block (`IdentifySource`): `identifyUrl` builds the request for a tap (a square of `2 * tolerance + 1` pixels centred on the tap, its `{bbox}` in EPSG:3857 metres) and `decodeIdentify` decodes the answer (GeoJSON, or a JSON list at a path; at most `MAX_IDENTIFIED_FEATURES`), `validateLayerDefinition` checks the block, and `isIdentifiable` and `cardOf` tell a layer that answers a tap from one that does not. Nothing asks yet: no port method, hook or tap route reads the block, so a layer that has one behaves as a plain tile layer. |

The `spatial` directory name describes generic geographic measurement and carries no dataset assumptions.

## Usage

Write unit tests against fakes, with no adapters:

```ts
import { createFakeServices } from "@mapcairn/core";

const services = createFakeServices();
```

Add a new port by following "Adding an adapter" in `ARCHITECTURE.md`: the port here, a fake and a contract suite, then a real adapter in `packages/web`.

Rendering belongs in `@mapcairn/map`, browser hooks in `@mapcairn/react`, and every adapter in `@mapcairn/web`.
